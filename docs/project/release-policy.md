パッケージを更新する前に目を通しておく変更履歴や互換性の前提と、公開物・CI検証の範囲をまとめています。公開済みの内容はnpmパッケージのバージョンとGitHub Releaseを基準にします。

## 更新前に確かめること

現在は`0.x`の開発段階です。とくに実験的なTSL APIは変更される可能性があるため、マイナーバージョンの更新でも利用箇所を見直してください。非推奨の別名には型定義の`@deprecated`を付け、置き換え先を示しています。

リポジトリの`CHANGELOG.md`で更新内容を読み、アプリケーションのロックファイルで採用バージョンを固定してください。ドキュメントが開発中のソースから生成されている場合は、インストール済みパッケージの型定義と照合します。

## 公開物と検証

npmパッケージにはJavaScript、型定義、Toon画像、ランタイムとBulletのJS・WASMが含まれます。ソースのチェックアウトから開発する場合は、これらのWASM成果物を生成する準備も必要です。

CIはライブラリのビルド、テスト、型の利用例、配布ファイル、WASMのABIと成果物の一致を検証します。公開前にはパッケージ内容とバージョンも検査します。サイトのビルド成功だけでライブラリのリリース検証は代替できません。

利用者向けの導入は[インストール](/getting-started/installation)を、ソースからの検証手順は[開発ガイド](/project/development)を参照してください。
