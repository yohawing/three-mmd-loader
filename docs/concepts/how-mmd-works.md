MMD（MikuMikuDance）のデータは、文字コード、ボーンの照合方法、変形や描画の順序に独自の約束事があります。このページでは、three-mmd-loaderがモデルとモーションを解釈してThree.jsへ反映する仕組みを整理します。

## ファイル形式と文字コード

MMDのファイルは形式ごとに文字コードが異なります。three-mmd-loaderのパーサーは、各形式を次のエンコーディングで読み取ります。

| 形式 | 役割 | 文字コード |
| --- | --- | --- |
| PMX | モデル（頂点、材質、ボーン、モーフ、剛体・ジョイント） | UTF-16LEまたはUTF-8（ヘッダーで指定） |
| PMD | 旧形式のモデル | Shift_JIS |
| VMD | モーション（ボーン、モーフ、カメラ、ライトなどの時系列） | Shift_JIS |
| VPD | 静止ポーズ（テキスト形式） | Shift_JIS |

MMDの座標系とThree.jsの右手系Y-upの違い（Z軸や回転の符号など）は、モデル読み込み時とランタイム、カメラ・ライト用ヘルパーが変換します。アプリケーション側で同じ座標変換を重ねないでください。

## 名前による照合

VMDやVPDに記録されたボーンとモーフの動きは、インデックス番号ではなく名前（文字列）でモデル側と照合されます。

ボーンはモデル内の日本語名、英語名、Three.jsの`bone.name`の順で一致するトラックを探します。モーフもモデル側のモーフ名と一致するトラックが適用されます。

この仕組みのため、別のモデル向けに作られたVMDを適用すると、名前が一致しないボーンやモーフは動きません。ファイル編集や変換で名前が文字化けした場合も、一致しなくなります。モデルが標準ボーンを持つかどうかを調べたい場合は、`/parser`の`detectStandardBones()`を利用できます。

## 1フレームの評価順

`model.update(seconds)`またはランタイムの`evaluate(seconds)`が1回呼ばれると、次の順序で状態が計算されます。

1. **VMD補間（`vmdInterpolation`）**：現在フレームのボーンとモーフを補間し、`morphOverrides`の適用、グループモーフ・ボーンモーフの展開、IK有効状態の更新を行います。
2. **付与変形（`appendTransform`）**：指定された親ボーンの回転や移動を、所定の割合で対象ボーンへ引き継ぎます。
3. **IK（`ik`）**：足首などの目標位置に近づくよう、ボーン列の回転を解きます（`{ ik: false }`で無効化できます）。
4. **物理（`physics`）**：剛体とジョイントのシミュレーションを適用し、スケルトンを更新します（`{ physics: false }`で無効化できます）。
5. **Three.jsへの同期**：`model.update()`や`runtime.tick()`が、評価結果をメッシュ、マテリアル、プロキシメッシュへ反映します。

`model.runtime.debugState()`の`stages`には、上記1〜4に対応する`vmdInterpolation`、`appendTransform`、`ik`、`physics`の各段階の結果が入ります。不具合を切り分ける手順は、[デバッグ](/guides/debugging)を参照してください。

## `model.root`の中身と描画順

`loadModel()`が返す`model.root`は`THREE.Group`です。通常のWebGL経路では、本体メッシュ（`model.mesh`）に加えて次の補助メッシュが子要素として入ります。

- モーフ分割ボディメッシュ（材質ごとのメッシュ。`morphSplit`が有効（既定）で、モーフデータが大きいと判定されたモデルだけに生成）
- 描画順プロキシ（`model.renderOrderMeshes`。`materialRenderOrder`が有効（既定）で、モーフ分割ボディがないときに生成）
- 輪郭線（エッジ）プロキシ（`model.outlineMeshes`、`outline: true`で生成）

描画順プロキシやモーフ分割ボディが有効なとき、元の`model.mesh`のジオメトリは描画範囲が0に設定され、実際の描画はプロキシや分割メッシュ側が行います。そのため、`model.mesh`だけをシーンに追加すると、モデルが映らなかったり輪郭線が欠けたりします。シーンには必ず`model.root`を追加してください。

描画順については、MMDはPMXで定義された材質の順番どおりに描画します。`materialRenderOrder: true`（既定）のとき、ローダーは材質の定義順に沿った`renderOrder`と材質ごとの影フラグを割り当て、Three.jsでもMMDに近い重なり方を再現します。

## 時間の扱いと物理の履歴依存

`model.update(seconds)`には、前フレームからの経過時間（差分秒）ではなく、モーション先頭を0とする**絶対秒**を渡します。

ランタイム内部では`frame = seconds * frameRate`の式でVMDのフレーム番号へ換算します。`frameRate`の既定値は`30`です。たとえば`1.5`秒を渡すと、45フレーム目が評価されます。

一方、物理演算は直前の状態と前フレームからの時間差に依存します。前回より前の時刻を渡した場合（巻き戻しやループ）は、物理ワールドをその時点のポーズで初期化し直します。そのため、先頭から通しで再生した結果と同じ姿勢になるとは限りません。再現が必要な比較や書き出しでは、開始状態、時間刻み、助走時間をそろえてください。
